# OBSERVABILITY

---

## 1. Structured logs

Every log line is JSON with a fixed envelope:

```json
{"ts": "2026-11-05T00:30:45Z", "level": "INFO",
 "logger": "titan.main", "message": "TITAN ready: 25 tools registered",
 "correlation_id": "40702ca1402d4b69a562fd88474affc4"}
```

`correlation_id` is generated by the middleware in `main.py` when a request arrives
without one and is echoed back to the client in the error envelope. It is attached to
every log line produced while handling that request, including the audit row.

**No sensitive data is logged.** Passwords, tokens and provider keys are never written to
the log; the `SecretStore` redacts values, and the audit `detail` field is limited to
non-sensitive identifiers (ids, counts, error class names).

## 2. Metrics

`GET /system/metrics` renders a Prometheus-compatible text exposition:

| Metric | Type | Labels |
|---|---|---|
| `titan_http_requests_total` | counter | `method`, `path`, `status` |
| `titan_http_request_duration_ms` | histogram | `method`, `path` |
| `titan_audit_events_total` | counter | `action`, `outcome` |
| `titan_tool_executions_total` | counter | `tool`, `status` |
| `titan_agent_runs_total` | counter | `agent`, `status` |
| `titan_gateway_calls_total` | counter | `provider`, `model`, `status` |
| `titan_gateway_latency_ms` | histogram | `provider`, `model` |
| `titan_research_documents_total` | counter | `connector`, `status` |
| `titan_memory_writes_total` | counter | `scope`, `kind` |
| `titan_memory_dedup_total` | counter | `scope`, `kind` |
| `titan_memory_deletes_total` | counter | — |
| `titan_translations_total` | counter | `target`, `status` |
| `titan_model_evaluations_total` | counter | `model` |
| `titan_workflow_runs_total` | counter | `workflow`, `status` |
| `titan_rate_limited_total` | counter | — |

The audit counter is asserted by the acceptance suite (AT-36), which is why the metric
names above are a contract rather than a wish list.

## 3. Health and capability probes

| Endpoint | Use |
|---|---|
| `GET /system/health` | liveness — `{"status": "ok", "version": "18.0.0"}` |
| `GET /system/capabilities` | a **live** report of 12 capabilities, each `available` / `degraded` / `blocked` with a human-readable detail |
| `GET /models/providers` | per-provider reachability and health |
| `GET /research/connectors/probe` | per-connector reachability and latency |
| `GET /security/summary` | RBAC, sandbox limits, egress allowlist, secret booleans |

The capability report is the operational anti-fake surface: it is computed from the
running system on every call, never from a static table.

## 4. Events

`ws://<host>:8000/ws/events` broadcasts agent runs, workflow transitions, research
progress and build completions to every subscriber, plus a periodic heartbeat.
